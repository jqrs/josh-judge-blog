title: Start with the question
description: A short note on making room to understand a problem before building the answer.

It's easy to start a software project with a tool in mind. A framework looks promising, a new model becomes available, or an API makes something suddenly possible.

But a tool isn't a question. Before choosing one, it helps to write down what needs to change for the person using the result.

## Three useful prompts

1. **What is difficult today?** Describe a specific moment, rather than an abstract category of problems.
2. **What would a better outcome look like?** Make it something you can observe.
3. **What is the smallest thing that could test the idea?** Give yourself a way to learn before committing to a large build.

The answers don't have to be perfect. Their purpose is to make the next step clearer.

A small, well-framed question can be a better starting point than a large collection of features.
